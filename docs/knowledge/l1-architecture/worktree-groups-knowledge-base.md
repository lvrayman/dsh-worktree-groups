## 1. 域概述

`src/` 是 DeepSeek Harness（DSH）桌面端插件 `dsh-worktree-groups` 的全部源代码域。
插件向宿主声明自己是 Cordis 组合包（`package.json` 的 `dsh.bundle.patch` 指向
`cordis.patch.yml`），由一个包同时提供**宿主进程侧**与**浏览器渲染进程侧**两套入口：
宿主侧以 `src/index.ts` 为入口注册 HTTP 端点，客户端侧以 `src/client.tsx` 为入口抢占
宿主侧栏槽位。两半在运行时**只经 HTTP 端点通信**，不共享进程内存。

本域负责：

- **按 git 仓归并侧栏分组**：把 DSH 原生侧栏里平级的「工作区」列表，替换为
  「项目 → worktree → 会话」三级树；指向同一个 git 仓的多个 dsh 工作区被归并成同一个项目节点。
- **暴露未注册的 worktree**：直接扫描 git 的 worktree 列表，使从未在 DSH 中注册过的
  worktree 也能被看见并在其下新建会话，注册动作推迟到用户首次使用时才发生（懒注册）。
- **worktree 生命周期管理**：提供新建与移除 worktree 的能力，并在宿主工作区注册表中
  同步登记或注销对应记录；移除 worktree 不删除分支。
- **会话归位与持久化**：维护一份本地 JSON 台账，使 worktree 目录被外部删除后，
  其会话仍能回到所属项目的 `history-worktree-session` 桶，而不是掉进「未分组」。
- **死工作区自动清扫**：在组装树之前，把「目录已死且有正面证据表明是非主工作树」的
  工作区记录从宿主注册表注销，只删注册记录，不碰磁盘、不碰会话日志。
- **交互态与手动排序持久化**：把展开态与三层（项目 / worktree / 会话）手动排序结果
  写入浏览器本地存储，跨刷新保持；存储不可用时静默退化为内存态。
- **安全边界守护**：对全部接受本机路径的端点实施白名单精确匹配、git 位置参数注入防护
  与目标路径的符号链接解析校验。

**技术栈**：TypeScript + Cordis 插件（`@deepseek-ai/cordis`，仅 `peerDependencies`）
+ React 客户端（`react` / `react-dom` / `@deepseek-ai/dsh-client-ui-primitives`）。
构建链为 `tsc` 编译宿主侧 + esbuild 打包客户端 bundle；`package.json` 的
`dependencies` 为空，运行时不引入任何第三方依赖。运行平台为 DSH Desktop 宿主
（Electron 主进程 + 客户端 shell 渲染进程），Node 侧要求 `>= 22`；移动端 N/A。

层次说明：

- **宿主进程层**的装配面只有 `index.ts` 一个文件，不含业务逻辑；端点面只有 `routes.ts`
  一个文件，却同时承担路由注册、宿主事实收集、安全校验与台账回写四件事，是宿主半边体量
  最大的源文件（1679 行），需要按功能面阅读。
- **能力组件层**（`git.ts` / `projects.ts` / `ledger.ts`）三者互不依赖，只共享 `types.ts`，
  不存在循环调用；`types.ts` 无运行时代码与 IO。
- **进程边界**是本域唯一的跨半通信通道：宿主半边注册端点，客户端半边发起请求；
  两侧没有共享内存、没有共享模块实例。
- **浏览器渲染进程层**中，装配面与渲染面各占一个文件，推导面与文案面是零依赖纯逻辑，
  只被渲染面消费，其编译产物可被 `node --test` 直接加载做行为覆盖。
- **宿主客户端 shell 服务面**全部经客户端装配面构造的桥接门面惰性访问，
  服务缺席时降级而不抛错。

## 4. 跨模块流程

以下每条只给名称、一句话目的、涉及模块链与模块粒度的概览图；
组件与实现细节一律落在 L2/L3 文档。

### 流程一 — 宿主侧数据装配到浏览器渲染的端到端链路

> 浏览器侧栏周期性地向宿主插件自有端点请求一份树快照，宿主侧合并多类宿主事实与 git 扫描结果
> 组装出树载荷，浏览器侧再把它摊平成渲染行画成三级树；这是本域的主干数据流。

**涉及模块**: WebClient（渲染面发起取数）→ ServerHost（端点面组装载荷）→
ServerHost（能力组件）→ TreeModel（推导行）→ WebClient（渲染面画行）

**流程概览**:

    WebClient       ServerHost      ServerHost      TreeModel       WebClient
    渲染面          端点面          能力组件        推导面          渲染面
    |               |               |               |               |
    |---------------> 请求树快照
                    |---------------> 读台账 / 扫 git 仓
                    <---------------| 宿主事实
                    |-------------------------------> 合成树载荷
    <-----------------------------------------------| 树载荷
    |-----------------------------------------------> 原始数据
    <-----------------------------------------------| 渲染行序列

**详细实现见**：[ServerHost 模块技术文档](../l2-modules/ServerHost模块技术文档.md)、
[WebClient 模块技术文档](../l2-modules/WebClient模块技术文档.md)、
[TreeModel 模块技术文档](../l2-modules/TreeModel模块技术文档.md)

### 流程二 — 用户拖拽排序写回链路

> 用户在三级树中拖动项目 / worktree / 会话行，落点被换算成新的手动顺序后写入浏览器本地存储，
> 并立即改变后续的渲染行序列；首次拖拽即把该层切换为「手动排序」模式。

**涉及模块**: WebClient（渲染面接线与范围判定）→ TreeModel（落点换算与生效顺序）→
浏览器本地存储（顺序持久化）→ TreeModel（顺序叠加）→ WebClient（渲染面重绘）

**流程概览**:

    WebClient         TreeModel         浏览器本地存储    TreeModel         WebClient
    渲染面/拖拽       落点换算          顺序持久化        顺序叠加          渲染面/重绘
    |                 |                 |                 |                 |
    |-----------------> 拖拽落点
    <-----------------| 范围校验（同层同容器）后回传新顺序
    |-----------------------------------> 写入手动顺序
                                        |-----------------> 读回顺序
                                                          |-----------------> 渲染行序列

**详细实现见**：[WebClient 模块技术文档](../l2-modules/WebClient模块技术文档.md)、
[TreeModel 模块技术文档](../l2-modules/TreeModel模块技术文档.md)

### 流程三 — worktree 生命周期管理链路

> 用户在项目行发起「新建 worktree」或在 worktree 行发起「移除 worktree」，请求经安全校验后
> 由宿主侧调用 git 完成落地或移除，并同步在宿主工作区注册表中登记或注销，最后回写台账。

**涉及模块**: WebClient（弹窗与请求发起）→ ServerHost（端点面安全校验）→
ServerHost（git 能力）→ 宿主工作区注册表 → ServerHost（台账回写）→ WebClient（刷新树）

**流程概览**:

    WebClient           ServerHost          ServerHost          宿主工作区注册表    ServerHost
    弹窗/请求           端点面/校验         git 能力            注册表              台账/响应
    |                   |                   |                   |                   |
    |-------------------> 创建 / 移除
                        |-------------------> 白名单与路径校验后调用 git
                        <-------------------| 执行结果
                        |---------------------------------------> 登记 / 注销
                        |-----------------------------------------------------------> 更新台账
    <-------------------------------------------------------------------------------| 结果（含注册失败警告）

**详细实现见**：[ServerHost 模块技术文档](../l2-modules/ServerHost模块技术文档.md)、
[WebClient 模块技术文档](../l2-modules/WebClient模块技术文档.md)

### 流程四 — 会话归位与死工作区清扫链路

> 宿主侧在组装树之前先清扫「目录已死」的工作区记录，再用台账与路径启发两条路径把
> worktree 已消失的会话接回所属项目的历史桶；两条路径都不命中则落入「未分组」，绝不静默丢会话。

**涉及模块**: ServerHost（端点面清扫与归属判定）→ ServerHost（台账能力）→
宿主工作区注册表 → ServerHost（项目合成能力）→ WebClient（渲染历史桶）

**流程概览**:

    ServerHost        ServerHost        宿主工作区注册表  ServerHost        WebClient
    端点面            台账能力          注册表            项目合成          渲染面
    |                 |                 |                 |                 |
    |-----------------> 读台账
    <-----------------| 归属快照
    |-----------------------------------> 注销已死工作区
    |-----------------------------------------------------> 归属判定（台账 → 路径启发 → 兜底）
                                                          |-----------------> 历史桶行

**详细实现见**：[ServerHost 模块技术文档](../l2-modules/ServerHost模块技术文档.md)

### 流程五 — 侧栏装配与文案本地化链路

> 宿主加载客户端条目后，插件以更低优先级注册自己的侧栏条目取得渲染权，同时注册自有词典
> 命名空间；渲染面从取词入口拿文案，宿主语言服务缺席时按组件内兜底词条表降级。

**涉及模块**: 宿主客户端 shell（槽位与语言服务）→ WebClient（客户端装配面）→
WebClient（文案面）→ WebClient（渲染面）

**流程概览**:

    宿主客户端 shell      WebClient             WebClient             WebClient
    槽位/语言服务         装配面                文案面                渲染面
    |                     |                     |                     |
    |---------------------> 槽位就绪
    <---------------------| 注册侧栏条目 + 词典命名空间
                          |-------------------------------------------> 构造服务桥接门面后挂载组件
                                                <---------------------| 取词
                                                |---------------------> 词条 / 兜底词条

**详细实现见**：[WebClient 模块技术文档](../l2-modules/WebClient模块技术文档.md)

## 5. 设计约定

| 约定 | 说明 |
|---|---|
| 宿主 / 客户端分离 | 同一包提供两套入口，宿主侧注册端点、客户端侧抢占侧栏槽位；两半只经本机 HTTP 通信，不共享内存与模块实例，因此任一侧的失败都不会直接把另一侧拖崩。 |
| 缺失即降级，绝不崩 | 宿主服务与客户端服务全部在**调用时**惰性读取，缺席时返回空数据或走兜底路径；插件加载本身不因任一宿主服务缺席而失败。 |
| 进程边界唯一化 | 跨半通信只有插件自有 HTTP 命名空间一条通道；客户端不直接读宿主进程内的数据结构，宿主不直接操作 DOM。 |
| 纯函数优先 | 树推导（`tree-model.ts`）与文案（`locales.ts`）是零依赖纯逻辑，不做 IO、不 import React 与宿主包；行为可被 `node --test` 直接覆盖。 |
| 推导与渲染分离 | 渲染面不参与任何分组推导，推导面不画 DOM；行序列由单一入口产出，同样输入永远得到同样输出。 |
| 单一可见性谓词 | 「树 / 搜索 / 容器存在性」三处判据共用一个可见性谓词，避免三套规则漂移。 |
| 运行时态与持久化态分离 | 运行时顶部区是纯运行时推导，刷新即重置，绝不写入持久化存储；唯一例外是新会话落表的写入意图编排，由独立台账避免重复写入。 |
| 持久化只落在两处 | 宿主侧落本地 JSON 台账（worktree 归属快照），客户端侧落浏览器本地存储（展开态与三层手动顺序）；存储不可用时静默退化为内存态，不阻断渲染。 |
| 破坏性操作需正面证据 | 死工作区清扫要求「有正面证据表明是非主工作树」才注销；整个仓目录消失时无法判定，此时不动手。移除 worktree 不删除分支。 |
| 路径输入全程校验 | 全部接受本机路径的端点实施白名单精确匹配、git 位置参数注入防护与目标路径符号链接解析校验，确保无法借端点在本机任意位置落盘或删除目录。 |
| 海拔分层（L1 / L2 / L3） | L1 只保留域概览、模块索引与跨模块流程名称；组件索引下放 L2，签名、状态机与实现细节下放 L3。每一层都用相对链接指向下一层，读者按海拔逐级下沉。 |
| git-version 锚定 | 全部知识库文档的 frontmatter 锚定同一提交 `9bd94252dd934c2fa8491977285e461b703f0f3e`，使文档陈述的代码事实可被精确定位与复现。 |
| 中文正文 + 英文标识符 | 正文使用中文，代码标识符、包名、路径与命令保留英文原文，避免翻译造成的检索与对照障碍。 |
| 图一律 ASCII | 全部架构图与流程图使用 ASCII / 制表符字符绘制，不引用外部图片，保证在纯文本环境与版本控制 diff 中可读可比较。 |
