# 需求：整体性能优化 + 会话列表渐进式展开

- **日期**：2026-11-14
- **状态**：已确认（AskHuman 2026-11-14）
- **来源**：用户反馈「插件性能有点差，新的 worktree 显示不及时；会话多时新增会话出现得慢」，并要求改造「展开其余会话」交互。
- **相关**：[设计](../design/2026-11-14-perf-progressive-expand.md) · [工作记录](../worklog/2026-11-14-perf-progressive-expand.md)

## 1. 背景与根因（实测，2026-11-14）

| 现象 | 实测证据 / 根因 |
| --- | --- |
| `/tree` 慢 | 运行中宿主上 `curl POST /dsh-worktree-groups/tree` 3 次：1.42 s / 0.71 s / 0.69 s，载荷 601 695 B（3753 个会话文件、12 个项目）。 |
| 会话全量扫盘两次 | `sessionController.list()` 内部经 `sessionQuery.listSessions()` 调 `sessionPersistence.list()`（读每个会话文件首行 + stat）；插件随后又自行调一次 `sessionPersistence.list()`。 |
| 台账每次请求都写盘 | `updateLedger` 每次把所有 worktree 的 `lastSeenAt` 刷成 `now` ⇒ `changed` 恒真 ⇒ 每个请求都 `JSON.stringify(…, 2)` + fsync 重写 352 KB 台账；`read()` 与 `update()` 还各读一遍盘。`lastSeenAt` 无任何消费者。 |
| 新 worktree 最长 ~60 s 才出现 | git 扫描缓存 TTL 30 s，且主路径的旧缓存条目在 `scanRepos` 中优先被采纳（新 worktree 入口的新鲜扫描被忽略）；叠加客户端 30 s 轮询。git 扫描与工作区 `stat` 均为串行。 |
| 新会话出现慢 | 客户端每次会话快照变化都 `abort` 在途请求并重新发起；单次请求 ~0.7 s，快照在此窗口内再变化就再次 abort ⇒ 活跃期内请求可能一直完不成；新会话必须等服务端整棵树重算才可见。 |

## 2. 决策（用户确认）

| 编号 | 决策 |
| --- | --- |
| PX1 | 「展开其余」改为渐进式：默认显示 5 条；第 1 次点击再展开 5 条，第 2 次再展开 10 条，第 k 次再展开 5·k 条（不超过剩余条数）。 |
| PX2 | 展开过至少一次后，更多行同时提供「收起」；全部展开完时只剩「收起」。点「收起」回到默认 5 条。 |
| PX3 | 收起（折叠）工作区 / worktree / 「最近」分区时，其内部全部会话容器的展开层级自动清零。 |
| PX4 | 底部「最近」默认 5 条，同样渐进式展开，**取消 100 条上限**。 |
| PX5 | 展开层级保存到 `localStorage`（收起工作区/worktree/最近时清零）。 |
| PX6 | 子代理模型：用户要求 DeepSeek Flash，但本会话路由不允许（`deepseek-v4-flash` 被拒），经确认改用 GLM。 |

## 3. 验收标准

### 3.1 性能（PERF）

- **PERF1**：同一进程内，`/tree` 的会话事实不再每个请求都全量扫盘两次；会话列表结果带缓存，宿主 `session/event` 或超时后才重取，并发请求合并为一次计算（single-flight）。
- **PERF2**：台账只在内容有实质变化时写盘；`lastSeenAt` 刷新节流（同一 worktree 至多每小时写一次）；台账读取走内存缓存（以文件 mtime/size 校验）。
- **PERF3**：git 扫描缓存改为「指纹校验」：`commonDir`、`commonDir/worktrees` 及其子目录的 mtime 指纹不变才复用，变了立即重扫 ⇒ `git worktree add/remove`（无论来自本插件、终端还是其他工具）后下一次 `/tree` 即可见；扫描与 `stat` 并行。
- **PERF4**：`/tree` 响应带 `ETag`，客户端带 `If-None-Match`，内容未变返回 304，客户端不重解析、不重渲染。
- **PERF5**：客户端取树不再「abort 重来」导致饥饿：同一时刻至多一个请求在途，期间的新触发合并为一次尾随请求。
- **PERF6**：客户端把宿主 `useSessions` 实时快照叠加到树上：树里没有、但能按 `cwd` 唯一匹配到某个 worktree / 非 git 工作区的新顶层会话**立即**显示；已有会话的标题、`updatedAt`、运行态、blank 态以实时快照为准。服务端返回后以服务端归属为准。
- **PERF7**：可见时轮询周期缩短（以 304 为主，开销可忽略），页面隐藏时暂停轮询，聚焦时立即刷新。

### 3.2 渐进式展开（PX）

- **PX-AC1**：容器顶层会话数 ≤ 5：无更多行。
- **PX-AC2**：> 5 时层级 L（默认 0）的可见条数 = `5 + 5·L(L+1)/2`（5、10、20、35、55…），封顶为总数。
- **PX-AC3**：有剩余时更多行显示「展开更多 n 个」，n = `min(5·(L+1), 剩余)`；L > 0 时同行提供「收起」；无剩余时只显示「收起」。
- **PX-AC4**：点击「收起」⇒ 层级归 0；折叠工作区 ⇒ 该工作区下所有容器层级归 0；折叠 worktree ⇒ 该 worktree 容器归 0；折叠「最近」⇒「最近」归 0。
- **PX-AC5**：「最近」默认 5 条，渐进展开，不再截断到 100 条。
- **PX-AC6**：层级持久化在 `localStorage`，刷新后保留；旧 `expandedAll` 存储不再生效。

## 4. 非目标

- 不改变会话归属规则、手动排序、顶部区、「最近」排序口径。
- 不做跨进程持久化的会话缓存；宿主重启后首个请求仍需一次全量列举。
- 不改宿主代码。
